## Priority issues

### P1 — Make the first test useful above the fold

Observed independently on desktop and mobile: a large empty history pushes normal-request and rule-challenge suggestions below the first viewport. On mobile the composer begins near y=765 at 390×844. The handoff action is also below the empty transcript. style.css:360 fixes .bench-messages at 340px; Editor.tsx:1297 renders history ahead of suggestions at 1330 and handoff at 1335.

Fix: use a compact empty state containing the two suggested requests, grow history after the first turn, and keep handoff near the test header/composer. Suggested command: $impeccable layout.

### P2 — Give new-character creation its own focus

Observed: the existing Hesta header/actions and editable character remain visible during the new-character wizard. Editor.tsx:526 renders starters separately from the existing editor at 528. The close-starting-points control lives inside More at 497.

Fix: show a focused creation view with Cancel and return to Hesta. Keep the old draft intact and restore its editor on cancellation. Suggested command: $impeccable distill.

### P2 — Complete accessible conversation and sprite interactions

Source-confirmed, not tested with a real screen reader: Chat.tsx:82 and Editor.tsx:1297 message containers lack log/live semantics, although thinking indicators are announced. Actual replies may require manual navigation. Editor.tsx:872–883 exposes buttons as radios without roving focus or arrow-key selection, and numeric Character frame labels do not describe appearance.

Fix: add a labeled conversation log with scoped announcements, avoiding duplicates; implement native/complete radio behavior with descriptive labels. Verify keyboard traversal and screen-reader replies. Suggested command: $impeccable harden.

### P2 — Put draft persistence where users can see it

Observed: Ready to test is visible, while persistence requires opening How saving works. Editor.tsx:507–515 combines browser storage, downloads, development files, restart behavior and village state.

Fix: show Draft saved in this browser only after storage succeeds, with an actionable failure state. Place download and development-save explanations beside their own actions. Suggested command: $impeccable clarify.

### P2 — Protect meaningful test history from accidental reset

Source-confirmed only: Editor.tsx:1292 directly invokes reset; 1270–1276 clears test state without confirmation or undo. The reviewer did not activate it.

Fix: confirm reset when meaningful history exists, or provide recoverable history/Undo. Leave empty-session reset lightweight. Suggested command: $impeccable harden.

## Cognitive load and emotional journey

Three of eight checklist items fail: single focus, one decision at a time, and minimal choices. Chunking, grouping, hierarchy, working-memory support and progressive disclosure pass. The five well-described role choices are a minor exception, not a reason to invent another step. The more consequential overload comes from the wizard sharing the existing editor.

The homepage builds confidence; guided setup reassures; overlapping draft contexts introduce uncertainty; the empty test creates the main loss of momentum. Source handoff provides a three-step ending, but successful completion was not tested.

## Persona red flags

- First-timer: cannot immediately see useful test prompts and may confuse a new draft with the existing character beneath it.
- Power user: direct game handoff exists before model testing but is buried under empty history; new-character entry requires several steps.
- Screen-reader/keyboard user: thinking status is present, but incoming replies lack log semantics; sprite radios lack expected arrow-key behavior. These are source findings pending assistive-technology validation.
